# MedArbeiter Zeiterfassung — working rules

Internal German employee time tracker for one company. Product truth lives in
`PRODUCT.md`, the visual system in `DESIGN.md`, per-surface strategy in
`.impeccable/surfaces/`. Read those before changing product behavior or design.

## Runtime: Bun only (no Node installed on this machine)

- `bun <file>`, `bun install`, `bun run <script>`, `bunx <pkg> <cmd>` — never `node`/`npm`/`npx`.
- Next.js runs entirely under Bun: `bun run dev` (dev server, port 3000), `bun run build`, `bun run start`.
- `bun:sqlite` for the database (never `better-sqlite3`). Bun auto-loads `.env` — no dotenv.
- `bun test` for tests (`bun:test`).
- E-Mail: `resend` + `@react-email/components`. **Not** `@react-email/render` — it statically imports `prettier/plugins/html`, and Turbopack renames the module while externalizing it and then cannot resolve it, which killed every server action that so much as pointed at `lib/mail.ts`. `serverExternalPackages` only moved the failure onto the render package itself. Rendering is `renderToStaticMarkup` (called through a runtime `import()`) plus `emails/text.ts`; do not add the package back.

## Project map

- `app/` — Next.js App Router. `(app)/` = authenticated shell: `/` = "Meine Zeit" — one frame, four URL-driven ranges `?ansicht=tag|woche|monat|konto` plus `?tag=`. Legacy links keep working: `?ansicht=heute` aliases `tag`, `?monat=` is read as a date, `/zeiten` and `/zeiten/konto` redirect here. `/spesen` = "Reisen & Spesen" — the same frame, two ranges `?ansicht=monat|jahr` plus `?monat=`, and `?neu=<datum>` opens the trip editor prefilled. `/abwesenheit` = "Abwesenheit" — the same frame, two ranges `?ansicht=monat|jahr` plus `?monat=`, and `?von=&bis=` opens the span editor prefilled. Its navigator is the only one allowed to page **forward** past today: a holiday is requested before it happens. `/kalender` = "Teamkalender" — the same frame again, two ranges `?ansicht=monat|jahr`, one lane per employee, visible to everyone and graded by role. `/protokoll` = the audit log — the same frame, `?ansicht=monat|jahr` plus URL-driven filters (`?bereich=&person=&akteur=&tag=&suche=&nur=alles&sortierung=alt&seite=`); Verwaltung sees everything, an employee sees their own record's trail. Manager-only `/team`, `/abschluss`, `/berichte`, `/mitarbeiter`, `/spesen/pruefen`, `/abwesenheit/pruefen`, `/apps`; `login/`, `druck/[monat]/` (print sheet, no shell), `api/export/` (CSV). The `(app)` layout mounts `ClockProvider` and `KopfSichtProvider` **around `AppShell`** (so the sidebar can read the same clock, and the bar can read what the content's Kopf is saying) + sticky `ClockBar`. The ClockBar is the **primary** home of stamp actions and the only one that is always visible; the sidebar's expanded "Meine Zeit" item mirrors the same state and the same `stamp()` from `useClock`. Do not add a third.
- `app/actions.ts` — all mutations (server actions). `app/providers.tsx` — Theme + i18n provider.
- `lib/db.ts` — schema + `getDb()` (SQLite at `data/medarbeiter.db`, WAL). Migrations are versioned via `PRAGMA user_version` + an append-only `MIGRATIONS` array — never edit a shipped migration (the baseline stays idempotent). `lib/settings.ts` — key-value settings with defaults (`mergeWindowMin()` etc.).
- `lib/time.ts` — domain logic (DB-bound). `lib/format.ts` — pure date/format helpers, safe for client imports. Never import `lib/time.ts` or `lib/db.ts` from a client component.
- `lib/arbzg.ts` — ArbZG rules (pure): break duty, 10 h cap, 11 h rest, Feierabend prognosis. `lib/feiertage.ts` — German public holidays, computed per Bundesland (pure). `lib/daytypes.ts` — day types + how each meets the Soll. `lib/attention.ts` — which past days need a human (`dayIssues` pure, `attentionIssues` DB-bound).
- `lib/pausenschnitt.ts` — die nachgetragene Pause (pure, client-importable): `pausenSchnitte()` rechnet aus, was eine Pause aus den Arbeitseinträgen eines Tages herausschneidet und was von ihnen bleibt, plus `schnittVerlust()`/`fmtSpanne()`/`schnittText()`. Eine Kopie der Regel, benutzt vom Server (`lib/time.ts` wendet sie an) und vom Dialog (`segment-editor.tsx` zeigt sie vorher an).
- `lib/pauschale.ts` — Verpflegungspauschale (pure, client-importable): the dated rate table, `satzFuer()`, `berechneSpesen()` day by day. `lib/spesen.ts` — the Reise record (DB-bound: CRUD, overlap, locks, status machine, receipt files). `lib/spesen-tafel.ts` — maps a Reise plus its stamped days into the flat payload the client tafel takes (own module: `lib/time.ts` already imports `lib/spesen.ts`).
- `lib/abwesenheit-arten.ts` — absence vocabulary and span arithmetic (pure, client-importable): the four arts, `istAntrag()`, `tageDerSpanne()`, `anspruchstage()`, `restanspruch()`, `fmtUmfang()` (the **one** formatter for "how much" — a 90-minute Freizeitausgleich must never read as "1 Tag"), and the two grading rules that keep exactly one copy of themselves: `ausserHausLabel()` (outward — Google, mail) and `sichtbareArt()` (inward — the Teamkalender). `lib/abwesenheit.ts` — the Abwesenheit record (DB-bound: CRUD, overlap, status machine, **the projection onto `day_types`**, Anspruch, AU files, `paragraf9Anwenden()`).
- `lib/kalendergitter.ts` — **the date axis, folded at the week boundary** (pure, client-importable): `kalendergitter(monat)` returns full Mo–So weeks with their KW, and `wochenraster(jahr)` / `rasterStufe()` do the same job at year resolution. This is what every month-shaped surface draws on. Not a time axis — that is `Tagesbahn`'s hour axis through one day. `lib/datumsachse.ts` — the older *unfolded* date axis; still drawn by the Protokoll's **year** band, where a per-day density genuinely reads as a strip. Nothing else uses it.
- `lib/protokoll-arten.ts` — the audit vocabulary (pure, client-importable): `AKTIONEN` names every mutation the app performs, its Bereich, its German label and whether it counts as an *Eingriff* (a human intervening) or *Routine* (stamping, logging in). Adding a server action means adding a meaning here — the same discipline as `sinnbilder.tsx`. `lib/protokoll.ts` — the record (DB-bound): `protokolliere()` appends a row and links it into the SHA-256 chain, `protokollSeite()` reads it back under filters, `protokollPruefen()` recomputes the chain, and the `beschreibe*()` helpers freeze a German description of a record *before* it is changed or deleted.
- `lib/totp.ts` — Einmalcodes nach RFC 6238 (pure Rechnung, aber server-gebunden: `node:crypto`, und das Geheimnis gehört nicht in den Browser): Base32, HOTP/TOTP, `otpauthParsen()`. `lib/zugangscodes.ts` — the shared-account record (DB-bound: `totp_konten` CRUD): the TOTP secrets of **shared** company accounts, replacing the office phone that used to be passed around. Its one rule: the secret never leaves the server — `aktuelleZugangscodes()` hands the page the finished code plus expiry, never the Base32 behind it, and a stored secret is not readable back even by Verwaltung. `/zugangscodes` shows each signed-in user the codes of their Leserkreis: every Zugang carries a visibility scope (`sichtbarkeit` = `alle | rolle | personen`, with role and person circles in `totp_konto_rollen`/`totp_konto_personen`; "Nur für mich" is `personen` with exactly the creator), cut in the SQL of `sichtbareZugangskonten()` like the Protokoll's `sichtbarFuer` — holders of `zugangscodes.verwalten` see every row (otherwise a mis-scoped entry could not be removed) with the scope as a visible badge (`sichtbarkeitText()`). Two rights, two reaches: `zugangscodes.erfassen` (every base role) lets a user create and maintain **their own** entries — "Nur für mich" or shared with chosen people, the creator always auto-included in the circle so their own key cannot vanish from their view; `zugangscodes.verwalten` additionally releases to *alle* or to selected **roles** (multi) and may edit/delete any entry (`darfZugangBearbeiten`). Editing (`zugangscodeAendernAction`) never shows the stored secret — an empty key field means keep it, a filled one replaces it, and the Protokoll records only "unverändert/ersetzt" (`zugangscode.anlegen/aendern/loeschen` — the fact, never the secret, same stance as passwords). The page groups rows personal→shared→alle (`gruppe` computed server-side), the create button lives in the Kopf's `werkzeuge` band like every page-level primary action, and one `ZugangForm` serves create and edit. `components/zugangscode-tafel.tsx` renders the rows: the server computes, the client only counts down (carrying the server/browser clock offset) and `router.refresh()`es at the period boundary. `components/qr-leser.tsx` is the enrollment scanner (camera via native `BarcodeDetector`, jsQR fallback, picked-image fallback — the only place `jsqr` is imported); it hands the decoded text back, the form decides whether it is an otpauth link, and manual paste always remains beside it. `components/zugangscode-filter.tsx` is the search/Dienst bar — like `protokoll-filter.tsx` it writes **only to the URL** (`?suche=&dienst=`), which is also why the 30-second `router.refresh()` keeps the filter.
- `lib/oauth-apps.ts` — Verbundene Apps: MedArbeiter als Anmeldestelle (DB-bound). OAuth 2.0 Authorization-Code for **own server-side apps only** — opaque tokens checked by DB lookup like the session cookie, no OIDC/JWT/new dependency. Three endpoints: `app/api/oauth/authorize` (never redirects to an unvalidated URI; missing session round-trips over `/login?weiter=…`, prefix-validated by `weiterZielGueltig()` on the login page *and* in `loginAction`), `token` (Basic or form client auth, RFC error vocabulary, code single-use with reuse revocation), `userinfo` (`sub`/name/email/role/`rechte[]`; `active = 1` sits in the join, so a deactivated account stops authenticating instantly — deactivation also calls `oauthTokensEntziehen()`). Client secret is Bun.password-hashed and shown exactly once (anlegen/erneuern, Startpasswort stance); codes/tokens stored as sha256. `/apps` (Recht `apps.verwalten`) manages clients — `components/app-anbindungen.tsx`; Protokoll: `oauth.app-*` (Eingriffe) + `oauth.app-anmeldung` once per code issuance (Routine), never per userinfo call, never a secret.
- `lib/mail-arten.ts` — the notification vocabulary (pure, client-importable): eight `MAIL_ARTEN`, each with a German label, who it goes to (`person` / `pruefende`) and whether it is `abwaehlbar`. Zugangspost (`zugang.willkommen`, `zugang.passwort`) is not — it is the only message that can reach someone *before* their first login, and a switch against it would play the account against itself. It also holds `MailInhalt`, the payload type: **one template, interchangeable payload**, exactly the relation `Monatsgitter` has to its cell contents. A new message is a new payload in `lib/benachrichtigungen.ts`, never a second template. `lib/benachrichtigungen.ts` — the meanings (DB-bound): `empfaengerMitRecht()` cuts the reviewer circle out of `hatRecht()` and never out of `role`, excludes the actor from their own notification, and the pure `inhalt*()` builders turn a record into a payload (tested in `tests/mail.test.ts` without a database or a mailbox). **Krank leaves the house only as „Abwesend"** here too — the rule itself is `ausserHausLabel()` in `lib/abwesenheit-arten.ts`, shared with `ereignisTitel()` so there is exactly one copy of it. `lib/mail.ts` — the transport: renders and hands to Resend, **never throws** (same stance as `protokolliere()` and `syncGoogleAbwesenheiten()`), and without `RESEND_API_KEY` writes the message to the console and books it as `uebersprungen` instead. `lib/mail-buch.ts` — the send log plus `mailKonfiguriert()`/`basisUrl()`, split off as a leaf because a page that only *reads* it must not drag the renderer into its bundle. `emails/nachricht.tsx` is the one template (React Email components; raw hex from `emails/farben.ts`, because an email has no `:root`), `emails/text.ts` the same payload as plain text — built from the payload, not from the HTML, because `toPlainText()` ran label and value together and pulled Prettier in. The HTML comes from `react-dom/server`'s `renderToStaticMarkup`, imported **at call time** (Next forbids it in the static App-Router graph). Wiring lives in `app/actions.ts` beside the calendar sync, always *after* the booking.
- `lib/auth.ts` — session cookie auth; `requireUser()` / `requireRecht(recht)` guards in server components. `lib/rechte.ts` — the permission vocabulary: every `Recht`, the `ROLLEN` bundles, `hatRecht()`.
- `lib/google.ts` — the Google account (DB-bound): config from `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (+ optional `APP_URL` behind a proxy), auth URL, code exchange, token refresh, disconnect. `lib/google-kalender.ts` — the calendar sync: `syncGoogleAbwesenheiten(userId)` **reconciles** the user's wirksame absences against the `google_kalender_eintraege` mapping (create/patch/delete all-day events in `primary`) instead of tracking single events — §9 BUrlG deletes and recreates Urlaub rows, so per-row bookkeeping would drift, exactly like the `day_types` projection. It never throws (same stance as `protokolliere()`: a calendar must not fail a booking) and makes zero API calls when the `stand` fingerprints match. The event title is `<Art> – <Name>`, the description names the MedArbeiter Hub as origin, each Art has a fixed `colorId` and default reminders are off; name and color are part of the `stand` fingerprint, so a rename or a display change migrates every event on the next sync. Called from every absence-mutating server action, from `userUpdateAction` on a name change, and from the OAuth callback; deactivating an employee removes their events and revokes the connection (logged as `oauth.google-trennen`). `app/api/google/start` + `app/api/google/callback` — the OAuth round-trip (CSRF state cookie, `?zurueck=login|profil`); the callback sets `users.google_einrichtung_abgeschlossen`, which gates the onboarding wizard's Google step. `components/google-knopf.tsx` — the embedded GIS flow the wizard prefers: Google's own personalized button + One-Tap prompt (identity only, used solely as a `hint`), then the calendar consent as a popup code flow whose code goes to `app/api/google/popup` (exchange with `redirect_uri=postmessage`); the redirect button stays as fallback, and the client needs the origin under "Authorized JavaScript origins" in the Cloud Console. `components/google-anmeldung.tsx` + `app/api/google/anmelden` — login via Google: the browser posts the GIS ID token, the server verifies it against Google's tokeninfo (`aud`, issuer, verified email — the browser is never believed) and maps it to an active account, `google_konten.google_sub` first, company email second; shared GIS types/loader live in `components/gis.ts`. Password login stays the base path — Google is the shortcut, never the only way in. `components/google-verbindung.tsx` on `/profil` shows/connects/disconnects; disconnecting removes our events, revokes the token, and does **not** reopen onboarding. `MOCK_GOOGLE_OAUTH=1` (dev only) re-enables the simulated connect button.
- `components/` — UI. `zeit-rahmen.tsx` is the frame **every route** renders into (Kopf / Bühne / Belege / Kontext rail; `buehne`, `nav`, `werkzeuge` and `sinn` are optional so a roster page fits too); `bereichs-leiste.tsx` is the one navigator — `BereichsLeiste` (four zooms), `MonatJahrLeiste`, `TagLeiste`, `MonatLeiste`, `StatusLeiste`, all on one `Navigator` shell. **`tagesbahn.tsx` is the only place a day is drawn** — `groesse="band|zeile|buehne"`, always horizontal, and it owns the drag-to-correct and drag-to-create pointer logic. `bahnen-stapel.tsx` stacks lanes on a shared axis with expand-in-place; `tages-tafel.tsx` is one day at working scale (Tag range, an opened lane, and `/team/[userId]` all use it); `konto-tafel.tsx` is the Zeitkonto range. Never add a second timeline component.
- **`components/monatsgitter.tsx` is the only place a month is drawn.** A real `<table>` of Mo–So weeks over `lib/kalendergitter.ts`, with an interchangeable cell payload — exactly the relation `Tagesbahn` has to its three `groesse` values. It replaced four near-identical bands that all drew days on an unfolded axis (measured: nine lanes for one absence, ~1 % ink, no weekday anywhere, and a year at 1.2 px per day). Its consumers: `team-kalender.tsx` (person marks + `BelegungsKurve` + `TeamJahresRaster`), `abwesenheit-gitter.tsx`, `reisen-gitter.tsx`, `protokoll-band.tsx`'s `ProtokollGitter`. `useGitterWahl` lives in the same module — the drag-select for an absence, which is why `tage-waehler.tsx` is gone. Add a month-shaped surface by adding a cell payload, never a second grid. Two payload-free modes belong to it too: `gesperrt` greys out a day that may not be picked, and `kompakt` is the same drawing at picker resolution — that is what `components/datum-feld.tsx` mounts.
- **`components/datum-feld.tsx` is the only date input.** Astryx' `DateInput` opens a `Calendar` whose week starts on **Sunday**: `Calendar` takes `weekStartsOn`, but `DateInput` never forwards it, and the column heads come from a hardcoded English list in `useCalendarDays` (so `lib/intl-de.ts` cannot reach them either). Rather than swizzling 1100 lines of vendor source for one number, the field pairs a `TextInput` with **the** Monatsgitter in its `kompakt` form — which has started on Monday, carried the KW and spoken German since the day it was written. Typing still works (`parseDatumEingabe` in `lib/format.ts` reads „4.8.", „04.08.2026", „4/8", ISO); unreadable input changes nothing. Never import `@astryxdesign/core/DateInput` again.
- Reisen & Spesen: `spesen-ansicht.tsx` pours `/spesen` into the same `ZeitRahmen`; `reisen-gitter.tsx` is the Bühne, `reisen-stapel.tsx` the Belege rows; `reise-tafel.tsx` is one trip at working scale and serves both the employee and the reviewer; `reise-editor.tsx` derives the amount live.
- `components/pruef-stapel.tsx` — the one row body of both review queues (person · period · subject · N figures · expand). `pruef-liste.tsx` and `abwesenheit-pruefliste.tsx` supply payload and decision bar only. `components/personen-tafel.tsx` — the one "row per person, numbers in columns" table, on the real Astryx `Table` with `useTableSortable`: Team, Monatsabschluss, Berichte and Mitarbeiter order columns from one vocabulary instead of hand-rolling four rasters.
- `protokoll-liste.tsx` is the row stack with expand-in-place; `protokoll-filter.tsx` writes **only to the URL**, so a filtered log can be bookmarked and handed on.
- **`components/melde.tsx` is the one gate every notice in the app goes through.** `useMelde()` wraps Astryx `useToast()` and maps a `MeldeTon` (`fehler | warnung | erfolg | hinweis`) onto the theme's own status colors, Astryx's two toast `type`s, a `Sinnbild`, and a default for whether it auto-hides (everything but `erfolg` stays until dismissed or replaced). A caller gives `titel`/`text`/`aktionen` for the common case, or a raw `body` when the shape doesn't fit (the correction queue's day list). All of it lands on the same inverted surface via `LayerProvider` in `app/providers.tsx`, and Astryx's `ToastViewport` stacks/staggers multiple at once on its own — no per-caller positioning. `--color-error`/`--color-success` got explicit `onDark.tokens` entries in `theme/medarbeiterTheme.ts` for this (see the comment there on why an inverted surface needs its tokens stated, not inherited) and pairings in `tests/kontrast.test.ts`. It carries two kinds of notice: a **fire-once action error** (`ton: 'fehler'`, no `uniqueID`, one toast per failure — every row/page-level server-action result across the app: `tag-ansicht.tsx`, `tages-tafel.tsx`, `abwesenheit-ansicht.tsx`, `reise-tafel.tsx`, `abwesenheit-pruefliste.tsx`, `lock-button.tsx`, `user-manager.tsx`) and a **kantengetriebene standing advisory** (a fixed `uniqueID`, fired from a `useEffect` keyed on the condition, replacing itself in place while the condition holds and dismissed when it clears — the ArbZG cap in `clock-bar.tsx`, the "nach 19:00 Uhr" reminder in `tag-ansicht.tsx`, the AU-missing/unsubmitted-draft counts in `abwesenheit-ansicht.tsx` and `spesen-ansicht.tsx`). What stays a plain Astryx `Banner` instead: form/dialog validation errors next to the field they belong to, and persistent data facts about the thing being viewed (`lockedNote`, the per-day `issues` list, the "Willkommen" onboarding copy, the "Zurückgewiesen" decision note) — none of those are transient events.
- `components/attention-toast.tsx` — "your record has holes", as **one toast, bottom right** (`useMelde`, `ton` follows whether a day needs correction), never a band in the flow. It renders nothing itself; it fires the toast from an effect and returns `null`. Suppressed on `/` — Meine Zeit says the same thing three times over already. Dismissal is per browser session, keyed on a signature of the issue set, so a new hole brings it back; a programmatic close (route change, logout) reaches `onHide` as `manual` too, hence the `vomBenutzer` ref that tells the two apart. The viewport is mounted by `LayerProvider` in `app/providers.tsx` — **inside** the i18n and theme providers, because `useToast`'s self-mounted fallback root sits outside both and would render an English dismiss label.
- **Waiting is said in three places, and nowhere else.** (1) **`components/ladegeruest.tsx` is the only loading screen in the app** — `LadeRahmen` redraws `ZeitRahmen`'s own bands in `ZeitRahmen`'s own classes (`.kopf-band`, `.zeit-blatt`, `.zeit-inhalt`, `.kontext-rail`), `LadeBlatt` does the same for the three sheets that carry no frame yet (Einstellungen, `team/[userId]`, its Konto), and four fillings match the four content shapes: `BahnenGeruest` (lanes, 76/fill/72 like the stack), `GitterGeruest` (Mo–So weeks at `--gitter-zellhoehe`), `TafelGeruest` (person × number, header row included), `ZeilenGeruest` (collapsed expandable rows), plus `FormularGeruest` and `KontextGeruest`. Every route has its own one-line `loading.tsx` picking a filling — the shape is what prevents the jump, so a route whose skeleton is the wrong shape is worse than none. A fifth filling means a fifth content shape, and that gets discussed first. **No spinner ever stands in for a page**; Astryx' own pulse (staggered via `index`, already stilled for `prefers-reduced-motion`) is the only motion, and `--color-skeleton` is warm paper #ece2c9 — 1.21:1 on the ground, as loud as Astryx' cold #ebebeb and no louder, because a placeholder that reads as gold would claim work was done before anything loaded. (2) **A button that starts a server action carries `isLoading`** from its own `useTransition`/`useActionState`; the two `logoutAction` forms have no such state and use `components/absende-knopf.tsx`, which reads `useFormStatus` from *inside* the form. (3) **A link that changes the page carries the pulse** — `components/verweis.tsx` (`Verweis`, and `LinkPuls` alone for the two places that build their own `<Link>`: Astryx' `Tab` via `as`, and the sidebar's `transitionTypes` wrapper). `useLinkStatus` only runs *below* a `<Link>`, so the puls is an empty child and `:has()` carries it back to the anchor (`.link-puls` in globals.css, `display: contents` so it adds no gap). A plain `next/link` is right only where the click does not leave the page or the browser takes over (`/api/beleg/…`).
- `components/app-hinweis.tsx` — the PWA install notice. Shows only when installing is actually possible (a captured `beforeinstallprompt`, or Safari on iOS), never before the third visit, and never again once dismissed. It stays a band in the flow: it is an offer, not a notice, and must not take the one corner reserved for notices.
- `components/app-nav.tsx` — the sidebar. It stays on its own paper, deliberately **outside** the content column's gold crown (user decision 2026-08-07): the shell reads as two sections, and the crown (clock strip + Kopf) belongs to the content. The logo mark is 40px (never smaller than its own wordmark), and the selected item wears gold wash + bronze ink + a 1px `--color-icon-accent` inset hairline (the Monatsgitter's open-day marking; pairings in `tests/kontrast.test.ts`). An item **may expand in place** (`nav-ausklapp.tsx`): a state line and **at most two** actions, hung on a thread line under the item's icon. Nothing floats — `SideNavItem`'s own `collapsible` does the work, so the motion is Astryx's (`grid-template-rows` 0fr→1fr). Opens on a click of the chevron *or* on half a second of hover (`NavVerweilen`; a hover-opened item closes again on leave, a clicked one stays). At most one open at a time. **Nothing may live only in there** — it is a shortcut, never the only path, so a touch device (no hover) loses no capability. Counts come from `lib/schnellzugriff.ts` (`navZaehler`, computed once per render, plain data only), and a count of 0 renders nothing. **Only where there is something to say**: Meine Zeit, Abwesenheit, Teamkalender, Reisen & Spesen, Abwesenheit prüfen, Berichte. Team, Spesen prüfen, Monatsabschluss, Protokoll, Mitarbeiter and Einstellungen are plain links — their badge already carries the count, and a branch that only restates it is a chevron that costs a click to learn nothing.
- `components/clock-bar.tsx` + `components/kopf-deckung.tsx` — the stamp strip and its **Deckung**: the bar states today's facts (seit / Std. heute / Feierabend or rest to Soll) **only where nothing else does**. The strip is the **top stripe of the Kopf band**, not a white band above it: full `--color-accent-muted`, no hairline at rest, hairline + `--shadow-low` only while it floats over scrolled content (`data-schwebt` from an IntersectionObserver sentinel, `.stempel-fuehler`). Meaning-carrying things standing on the wash carry their own edge: the gold primary button and the accent dot a bronze hairline, the orange pause dot a warning-text hairline (2.78:1 on the wash without it). On the phone (≤920px, fixed to the bottom edge) the strip returns to white and the button hairline comes off. It never spells the status out — the button beside it already names the next action. Coverage is `URL ∧ im Bild`: `zeitAusUrl()` (`lib/bereiche.ts`, shared with `app/(app)/page.tsx` so the two can never disagree) says whether this is the Tag range on today, and `HeuteDeckung` — rendered by `ZeitRahmen` when `decktHeute` — reports via IntersectionObserver whether that Kopf is still on screen. The URL half is server-known, so the bar never flashes on hydration. The ArbZG advisory and a stamp error no longer live in the bar itself — they're a `melde()` (`ton: 'warnung'` / `'fehler'`) like every other notice. The advisory fires edge-triggered: once per change in `hint`'s text (a new state, or the break-deficit countdown), replacing itself in place via a fixed `uniqueID` rather than stacking; it goes away when `hint` turns `null`. A stamp error is a one-off event and gets its own toast each time.
- `components/sinnbilder.tsx` — **the icon vocabulary: one meaning, one sign.** Typicons via `react-icons/ti`
  (context-free — the library only touches `React.createContext` when it exists — so server *and* client components may use
  it). Call sites name a meaning (`<Sinnbild sinn="einstempeln" />`), never a glyph; `umriss()`/`gefuellt()` give the
  component form Astryx wants for `SideNavItem.icon`/`.selectedIcon` and `TextInput.startIcon`. Typicons has **no weight
  axis**, so instead of three weights there are two forms — `voll` (the default; the mass carries the 3:1 floor at every
  size) and `umriss` (only for "not selected / not running", and only where Typicons ships an `…Outline` counterpart;
  otherwise it falls back to `voll`). Add a new icon by adding a meaning here; never import an icon package anywhere else.
  `theme/icons.tsx` re-registers Astryx's own built-ins to the same family.
- `theme/medarbeiterTheme.ts` — the design tokens SOURCE. After editing run `bunx astryx theme build theme/medarbeiterTheme.ts -o theme/medarbeiter.css` (regenerates css/js/d.ts). Never hand-edit the generated files.
- `lib/avatar.ts` — the profile-sign vocabulary (pure, client-importable): the ten illustration keys, `AVATAR_TYPEN`/`AVATAR_MAX_BYTES` and `avatarQuelle()`. `lib/profilbild.ts` — the uploaded photo (DB- and fs-bound, the same split as `pauschale.ts`/`spesen.ts`): stored under `data/avatare/<uuid>.<ext>` like a Beleg, name never from the client, extension from the allowlist, and replacing or removing always deletes the old file so no orphaned likeness is left behind. **The illustration set stays the fallback** — that is why `avatar_key` is still required and why an account is never signless. Served by `app/api/avatar/[userId]`, which is deliberately wider than `api/beleg`/`api/au`: **any signed-in** account, because a profile picture exists to be recognised by the team; unauthenticated is 403. The Protokoll records `profil.bild` as "gesetzt"/"entfernt" — the fact, never the file, the same stance as a password.
- **Server Actions take 12 MB** (`serverActions.bodySizeLimit` in `next.config.ts`). Next's default is **1 MB**, which is below every file this app actually accepts (Beleg and AU 10 MB, Profilbild 5 MB) — a phone photo therefore died with an opaque „Unerwarteter Fehler" instead of the German message the server-side check is there to give. Raise this alongside any file limit.
- `scripts/seed.ts` — `bun scripts/seed.ts` creates the admin; `--demo` adds synthetic demo employees/times (never present demo data as real).
- `locales/de.json` — German catalog for Astryx built-in strings; extend it when a new component surfaces an English built-in.

## Domain invariants (do not break)

- Segments are `arbeit | pause`, one calendar date + minutes-from-midnight, never crossing midnight. `end_min IS NULL` = running (today) or forgotten clock-out (past day = anomaly). One exception to "never auto-close": a segment still open from *exactly yesterday* within 12h elapsed is a running night shift — the next stamp action splits it at midnight. Anything older is never auto-closed and is fixed by manual correction.
- Stamp fumbling never fragments the record: re-clock-in within the merge window (settings, default 2 min) reopens the previous segment; a sub-window pause between two work blocks is absorbed; Ausstempeln is undoable for 30 s (`undoStamp`, DB-derived, no token).
- **Eine nachgetragene Pause ist keine Überschneidung, sondern ein Schnitt.** Wer die Pause zu stempeln vergisst, hat den Tag längst am Stück erfasst — die Pause liegt zwangsläufig *in* der Arbeit, und abweisen hieße: gar nicht nachtragbar. `validateSegment` lässt Pause-über-Arbeit daher durch, `createSegment`/`updateSegment` schneiden sie in derselben Transaktion heraus (`lib/pausenschnitt.ts`): der Rest **rechts** behält die Zeile, damit ein laufender Eintrag laufend bleibt, der Teil davor wird zur neuen Zeile, ein ganz überdeckter Eintrag entfällt. Der Dialog sagt vorher an, was passiert (warnender Banner statt gesperrtem Speichern), das Protokoll hält den Schnitt als Wert derselben einen Handlung fest. Alles andere bleibt eine Überschneidung: Arbeit über Arbeit, Pause über Pause, Arbeit über Pause. Das Ziehen in der Tagesbahn ist an den Nachbarn geklemmt und kann gar nicht erst überlappen.
- **An absence is a span, never a day.** `abwesenheiten` (von/bis + art + status) is the record; `day_types` is its **projection** and is rebuilt wholesale for the touched range (`neuProjizieren`) rather than patched, so it cannot drift. Hand-written rows (`abwesenheit_id IS NULL` — i.e. calendar corrections) are never overwritten. Nothing sets a day type directly any more; `day-type-control.tsx` is gone.
- Four arts, two kinds of act. *Antrag* (Urlaub, Freizeitausgleich) runs `entwurf → eingereicht → genehmigt | abgelehnt` and takes effect only when approved; *Meldung* (Krank, Fortbildung) is created as `gemeldet` and takes effect at once. `feiertag` is not an art — it stays computed from the Bundesland. The temporal guard is the **mirror** of the Reise's: a trip is submitted after it ends, an absence before it starts (and retroactively), so `einreichen` checks no time window at all.
- **Only Freizeitausgleich has a part-day, and only on a single day.** `abwesenheiten.minuten` (NULL = the whole day) is accepted for `art = 'freizeitausgleich'` with `von = bis`, bounded by that day's own Soll; `neuProjizieren` carries it onto the one `day_types` row. Every other art, and any multi-day span, stays whole-day by construction. **The balance arithmetic is deliberately unchanged**: `effectiveSollMin` still charges the full Soll for `abgebaut`, so the Zeitkonto falls by exactly the hours *not* worked — a 2 h part-day with 6 h stamped nets −2 h on its own. What `minuten` therefore changes is the *expectation*: a part-day is only partly accounted for, so it does **not** excuse a missing entry (`dayIssues`' `dayTypeMinuten`, `excusedDays`). Without that, forgetting to stamp the remaining hours would silently cost the whole day.
- **An Antrag records that the supervisor was asked.** `abwesenheiten.ruecksprache_vorgesetzte` is required to *create* an Urlaub or Freizeitausgleich (never a Meldung — nobody asks permission to be ill), and deliberately **not** re-required on update: Verwaltung correcting an approved Urlaub must not have to attest a conversation that was not theirs, so an omitted value means "unchanged", never "revoked". It is not a second approval — the reviewer sees it beside the request as a fact, and §9 BUrlG's split carries it onto the remaining Urlaub.
- Spans of one person never overlap — except a Krank over an Antrag, which §9 BUrlG requires. Krank wins the projected day either way; only a Krank **with an AU** splits the approved Urlaub and returns those days (`paragraf9Anwenden`). Without the certificate the leave stays spent, which is exactly what the statute says.
- Urlaubsanspruch: `users.urlaubstage_jahr` plus a manually entered `urlaub_uebertrag` per year. Deducted **on approval** — a submitted request is shown separately and binds nothing. Only days with a Soll count, so a weekend or holiday inside a holiday costs nothing. Nothing about carry-over or forfeiture is computed; that is Verwaltung's entry, deliberately.
- **Krank leaves the house only as „Abwesend".** The Google Calendar sync titles a Krank span „Abwesend – <Name>", never „Krank" — an Art. 9 GDPR health datum must not land on Google's servers — and gives it the quietest color in the palette (graphite) so the color says as little as the title. Same grading as the Teamkalender: the calendar shows *that* someone is away, not why. Urlaub/Freizeitausgleich/Fortbildung keep their German labels **and carry their `notiz` plus any part-day amount into the event description** (`ereignisBeschreibung()`); Krank gets the bare origin note and nothing else, guarded on `art` at that function rather than trusting that `notizFuer()` upstream kept the column NULL — this is where data leaves the house, so the boundary holds the rule. The description is part of `ereignisStand()`'s fingerprint, otherwise an edited note would never re-sync.
- **Krank carries no note field, anywhere.** It would be the first place a diagnosis lands, and that would put an Art. 9 GDPR health record in a time tracker. Dates and the AU file, nothing else. AU files live under `data/au/` (separate from `data/belege/`) behind `app/api/au/[id]/route.ts`, 403 to anyone but the owner and Verwaltung.
- Verwaltung approving its own absence is allowed — there is no second instance — and recorded as `selbst_genehmigt`, shown beside the record rather than hidden.
- Zeitkonto: a day counts when it has entries or a day type. Urlaub/Krank/Feiertag set the effective Soll to 0 (balance-neutral), Fortbildung counts as having worked the Soll, Freizeitausgleich spends the Soll from the balance. A past day with an unfinished entry is *uncountable* — never counted as zero — and a working day with neither entry nor day type is excluded and reported. `zeitkontoSummary()` returns all of that so the figure needs no footnote.
- Nothing before `firstRecordedDate(userId)` may be called a missing day.
- Per-employee weekly Sollzeit (`users.weekly_minutes`) spread over Mo–Fr.
- Locked months (`month_locks`) are read-only for everyone; Verwaltung must unlock to edit. Locking requires no open segments, no *eingereichte* Reise in the month, and a completed month.
- **Spesen are computed per calendar day, never from total hours.** Single-day trip: ≥ 8 h absence → half rate, below → nothing. Multi-day: half rate for the arrival and the departure day regardless of hours, full rate for every calendar day fully in between (`2 × halb + (Tage − 2) × voll`). Once a trip crosses midnight the elapsed hours stop mattering — a 50 h and a 58.5 h trip over three calendar dates cost the same.
- The rate table is **dated** (`STANDARD_SAETZE`: 14/28 € until 2025-09-30, 10/20 € from 2025-10-01) and editable in Einstellungen. Which tier applies is decided by the trip's **departure date**, so a trip across the cutover keeps one rate instead of switching mid-claim. The tier in force is frozen onto the Reise at Einreichen, so a reviewed claim never changes its amount later.
- A Reise spans whole calendar days and never overlaps another Reise of the same person. Pauschalen are derived, never stored — only the frozen rate pair is. An Entwurf may reach into the future; Einreichen requires the trip to be over. Only the owner may einreichen; only Verwaltung may genehmigen/zurückweisen; editing a genehmigte Reise (Verwaltung only) returns it to `eingereicht`, editing an abgelehnte returns it to `entwurf`.
- Receipt files live outside `public/` under `data/belege/<Jahr>/<uuid>.<ext>` (extension and MIME from a fixed allowlist) and are served only through `app/api/beleg/[id]/route.ts`, which answers 403 to anyone but the owner and Verwaltung.
- **A notification never fails a booking, and never carries what it must not.** Mail goes out *after* the record is written, `sendeMail()` cannot throw, and the whole feature switches off in Einstellungen without anything else changing. `users.mail_abbestellt` stores the **opt-out**, not the opt-in, so a later-added `MailArt` reaches every existing recipient instead of silently nobody. `mail_versand` is the delivery log — deliberately *not* in the Protokoll (a message is not a change to the record, and that chain is a proof about the record, not a postbook) and it holds recipient, art and subject only: a start password belongs in a send log as little as in the Protokoll.
- Corrections record `edited_by` — the audit trail payroll relies on.
- **Every action needs a named right, and roles are only bundles.** `lib/rechte.ts` is the vocabulary (pure, client-importable): 18 Rechte, five Rollen (`mitarbeiter`, `fulfillment`, `vertrieb` = base rights over the own record; `verwaltung`, `geschaeftsfuehrung` = all rights), per-account extras in `benutzer_rechte`. Checks go through `hatRecht()` / `requireRecht()` — never `role === '…'`. The session user carries the effective set (`user.rechte`, loaded in `getSessionUser()`); where it is absent, `hatRecht` falls back to the role's bundle. Extras only ever *add* — the base bundle is what a role guarantees. Where the docs say "Verwaltung sieht/kann", read "wer das entsprechende Recht trägt". Self-lockout is blocked twice: you cannot strip yourself of `mitarbeiter.verwalten`, and the last active account holding it cannot be deactivated.
- **The Protokoll is append-only, and the database enforces it.** Two triggers (`protokoll_unveraenderbar`, `protokoll_unloeschbar`) abort UPDATE and DELETE; a rule that lives only in the app holds only as long as everyone goes through the app. Each row carries `hash = sha256(vorher_hash ‖ its own content)`, so removing or editing a row past the triggers breaks the chain at a findable place. `kettenText()`'s field order is part of the proof and may never change — reordering it would invalidate every chain ever written. Actor name and role are frozen per row: a renamed employee must not rewrite history, which is also why the table carries **no foreign keys**.
- **Every mutation is logged, including the refused ones.** `protokolliere()` never throws — a log that fails a booking does more damage than a missing line, because then the time was not recorded at all. A failed write is reported to the console and leaves a gap the chain check finds anyway. Never log a password (the reset logs the fact, not the value) and never log a diagnosis (Krank has dates and a filename, nothing else).
- **An employee sees their own trail, Verwaltung sees all of it** — and the cut is made in `protokollSeite()`'s SQL (`sichtbarFuer`), never in the rendering. Art. 15 GDPR transparency and the basis on which someone can contest a correction.
- **The Teamkalender grades by payload, not by CSS.** For a non-Verwaltung viewer the `art` of *someone else's* absence is never sent to the browser (`app/(app)/kalender/page.tsx` sets it to `null`); what reaches the client is readable. Colleagues see that someone is away, Verwaltung and the affected person see why. Drafts and rejected requests are not shown at all.

## Quality bar (learned in review — keep these true)

- **German only.** Every user-visible string. Astryx `FieldLabel` hardcodes English "Required"/"Optional", so `isRequired`/`isOptional` props stay UNUSED; validate server-side with German messages.
- **One frame, every route.** `ZeitRahmen` carries all eleven surfaces, not just Tag/Woche/Monat/Konto: a route never invents its own page header, navigator, or column topology. The rule used to hold only inside "Meine Zeit" while six Verwaltung pages built `Heading + grey line + switcher` by hand — the split ran exactly along the employee/manager border, and every one of those pages already had its headline figure buried in the grey line. A page without a period passes no `nav`; a page without a timeline passes no `buehne`. Content is capped at 1180px (`.zeit-blatt`) while bands stay full-bleed.
- **Person × number is a `Table`, not an `HStack`.** `personen-tafel.tsx` on the real Astryx `Table`; every column comes from its vocabulary and every heading sorts. Four hand-built rasters with 74 hardcoded `inlineSize:` widths preceded it — Ist/Soll/Saldo was 90 px on Monatsabschluss and 100 px on Berichte, and payroll could not ask who deviates most.
- **Spesen sind kein Gold.** Gold means worked time and the primary action. Money is a plain fact in primary ink, and the Abwesenheitsspange (the absence bracket under a lane) is stone `--color-text-secondary` at full opacity — never bronze, never faded.
- **Gold discipline.** Brand gold `#e1b025` means work/primary action; text/icon gold is bronze (`--color-text-accent` #7c5f05, `--color-icon-accent` #8f6e06) because raw gold fails contrast on white; on-accent ink is dark, never white. Warnings are ORANGE (never yellow — it would impersonate the brand). One primary button per view.
- **Contrast floors.** Text ≥4.5:1; non-text UI ≥3:1. Computed in `tests/kontrast.test.ts` — add every new pairing there. Brand gold cannot reach 3:1 on a light ground, so meaning-carrying gold surfaces wear a 1px `--color-icon-accent` hairline (`.arbeit-flaeche`); the boundary carries the contrast, not the fill. Pause fill is `#8b8474` for the same reason.
- **The inverted surface says its own colours.** The toast is the one place in the app that sits on ink (`--color-background-inverted` = `#1c1917`, the house ink and not Astryx's cool `#0A1317`). Astryx assumes `MediaTheme`'s `color-scheme: dark` flips every `light-dark()` token; measured in the browser it does not — a custom property resolves where it is *declared* (`:root`, light), not where it is used, so stone `#67625a` (2.8:1) and bronze `#7c5f05` (2.0:1) would land unreadable on that ink. `onDark.tokens` in `theme/medarbeiterTheme.ts` therefore states the dark halves outright. Anything new put on an inverted surface must state its token there too, and add the pairing to `tests/kontrast.test.ts`.
- **A11y.** DOM order = visual order at every breakpoint (mobile stamp card is a separate `.nur-mobil` instance, not a CSS reorder). No `role="img"` on containers with interactive children. Focus rings via `--color-icon-accent`. Respect `prefers-reduced-motion` for any animation.
- **One gesture per surface, distinguished by target and not by direction.** `Tagesbahn` owns drag-across-free-track to record an entry; the **Monatsgitter** owns drag-across-calendar-days to request an absence. Two different surfaces, so a slightly diagonal drag can never be a coin flip between "recorded four hours" and "requested a week off". This is why the date gutter (`tage-waehler.tsx`) could be deleted: it only ever existed because the lane had no free surface left. The drag is never the only way — a plain click on one day does the same thing, so touch and keyboard lose nothing, and the day column in the time stack stays a plain link to the same editor.
- **A dialog that grows with its input must scroll.** Astryx caps `Dialog` at 75vh and its inner column is `overflow: hidden` — content past that is clipped, not scrollable, and the save button becomes unreachable. Both computing editors grow with what is typed (a row per travel day, a field per calendar day). `.tafel-rumpf` in globals.css is the fix, and `min-block-size: 0` is the part doing the work. Put the class on whatever element sits beside `DialogHeader` — the `<form>` in the Reise editor, the `VStack` in the Abwesenheit editor.
- **Motion.** Two authored moments, no more: the breathing live tip (gated `isOpen && isToday`) and the lane cascade on a range change. The sidebar's expanding item is deliberately *not* a third — it rides Astryx's own `grid-template-rows` transition on the same `--duration-medium`/`--ease-standard` pair, which `.bahn-ausklapp` already describes. **Nor is the Deckung handover in the stamp strip** (`.stempel-angaben`), and **nor is the install notice** (`.app-hinweis`): the same 0fr↔1fr track transition, turned to whichever axis the element is laid out on — columns beside the actions on the desktop, rows above them on the phone, rows for the notice. **Nor is the attention toast** — its entrance is Astryx' own `@starting-style` on `--duration-fast`/`--ease-standard`, already gated for `prefers-reduced-motion` in the component. **Nor is the renewing Zugangscode**: the span is keyed on the code, a new value remounts it, and a transform-only rise animation plays on mount (`--takt-schritt`/`--schwung-an`; keyframes, because the `@starting-style` transition got coalesced with the row rebuild and never showed) — state indication for digits that would otherwise swap silently under the eyes of someone copying them. Beside it `CodeRing` says *when* it changes: a depleting SVG arc, seconds-ticked from React with a 1s linear transition filling the gap, warning orange for the last five seconds (arc colors contrast-tested). Both gated in globals.css. Astryx does not gate the 0fr↔1fr transitions for `prefers-reduced-motion`, so globals.css does. Entrance animations move `transform` only — never `opacity`, which can strand content if the animation does not tick. Transitions use `--duration-*`/`--ease-standard` tokens and everything is `prefers-reduced-motion` gated.
- **Server/client boundary.** A `'use client'` module may not export plain values a server component imports (they arrive as client references), and a server component may not pass functions to a client one. Shared constants live in leaf modules like `lib/bereiche.ts`; pass data, not callbacks.
- **Icons are a vocabulary, not decoration.** Every glyph comes from `components/sinnbilder.tsx` and is named by meaning, so
  the same action wears the same sign everywhere. Icons never speak alone — each sits beside its label and is always
  `aria-hidden`. Default tone is `erben` (currentColor) so a glyph in a gold button inherits the dark ink; explicit tones are
  contrast-tested in `tests/kontrast.test.ts` like any other meaning-carrying surface (≥3:1). Only `react-icons/ti` —
  do not add `lucide-react`, Phosphor, or any other icon set alongside it. One scoped exception:
  `components/dienst-zeichen.tsx` is the single place `react-icons/si` (Simple Icons) is imported — **brand marks**, not
  meanings, shown only beside a Zugangscode's service name (`markeFuer()` recognizes terms like „Google" in the Dienst).
  Self-hosted from the package, never cdn.simpleicons.org (a CDN request would tell a third party which services the
  company uses); an unrecognized or trademark-removed brand (Microsoft, Slack) falls back to the `zugangscode` Sinnbild.
- **Fonts are self-hosted** via `next/font` (variables `--font-poppins`/`--font-figtree`); never add Google Fonts `<link>` tags.
- **Astryx rules** (block below): components own layout — no raw `<div>` layout; tokens only, no raw hex/px in UI code except where a token cannot express it (document why, as done in globals.css); custom visual grammar (timelines) uses semantic elements + `var(--…)` tokens.
- The direction contract is the HTML comment in `app/layout.tsx` — keep it in the emitted markup.
